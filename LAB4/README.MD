# LAB4 3R Manipulator Control System

A simulation system of a 3R robotic arm utilizing ROS 2 Humble. The system features Inverse Kinematics control, Jacobian-based Teleoperation with singularity avoidance, and dynamic workspace visualization.

![System Architecture](controller_node%20.png)
*(Image generated from system architecture)*

## Features

- **All-in-One Launch**: Starts the Robot Description, RViz, Controller, and Workspace Visualizer in a single command.
- **Dynamic Workspace**: Visualizes the robot's reachable workspace as a PointCloud2 in real-time by computing Forward Kinematics on random samples.
- **Custom Teleoperation**: Jog control using keyboard inputs mapped to end-effector velocities.
- **Control Modes**:
  - **Mode 1 (IPK)**: Inverse Kinematics control to a specific target pose.
  - **Mode 2 (Teleop)**: Jacobian-based velocity control with singularity warnings.
  - **Mode 3 (Auto)**: Autonomous movement to random targets generated by the system.
- **Safety**: Checks for singularities (Determinant of Jacobian) and ground collisions ($z < 0$).

## Installation

**1. Install ROS 2 Humble**

[Install ROS 2 packages](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html)

**2. Install Python Dependencies**

Required for kinematics and spatial math calculations used in `controller_node.py` and `workspace_node.py`.

```bash
pip3 install numpy
pip3 install roboticstoolbox-python
pip3 install spatialmath-python
```

**3. Install ROS Dependencies**

```bash
sudo apt install ros-humble-desktop-full
sudo apt install ros-dev-tools
```

**4. git clone**

```bash
git clone --branch LAB4 https://github.com/PPHUSIN/FRA502-LAB-6645.git
```

**5. Build the Package**

Go to your workspace (e.g., ~/LAB4) and build:

```bash
cd ~/FRA502-LAB-6645/LAB4
colcon build
source install/setup.bash
```

## Usage

Open 2 terminals to run the full system.

### Terminal 1: Main System

Launches the Robot State Publisher, RViz, Controller Node, Workspace Visualizer, and Random Pose Generator.

```bash
ros2 launch lab4_robot_description lab4_system.launch.py
```

### Terminal 2: Teleop Input

Runs the custom keyboard teleoperation node to send velocity commands (`/cmd_vel`).

```bash
ros2 run lab4_robot_description teleop_node.py
```

## Control & Mode Switching

The robot is controlled via the `controller_node`. You can switch modes using ROS 2 Service calls defined in `SetRobotMode.srv`.

### 1. Teleoperation Controls (Terminal 2)

**Ensure you have switched to Mode 2 first.** Focus on Terminal 2 to use these keys defined in `teleop_node.py`:

| Axis | Increase (+) | Decrease (-) |
|------|--------------|--------------|
| Linear X | `w` | `s` |
| Linear Y | `a` | `d` |
| Linear Z | `q` | `e` |
| Angular X (Roll) | `u` | `o` |
| Angular Y (Pitch) | `i` | `k` |
| Angular Z (Yaw) | `j` | `l` |
| **Stop** | `Space` | |
| **Quit** | `Ctrl+C` | |

### 2. Switching Modes (Service Calls)

Open a new terminal to send service requests to `/set_mode`.

#### Switch to IPK Mode (Mode 1)

Moves to a specific coordinate provided in the command using Inverse Kinematics.

```bash
ros2 service call /set_mode lab4_robot_interface/srv/SetRobotMode "mode: 1
target_pose:
  position:
    x: 0.3
    y: 0.0
    z: 0.6
  orientation:
    x: 0.0
    y: 0.0
    z: 0.0
    w: 1.0
teleop_frame: 0" 

```

#### Switch to Teleop Mode (Mode 2)

Enables velocity control via `teleop_node.py`. teleop_frame: 0 = "EndEffector" teleop_frame: 1 = "World"

```bash
ros2 service call /set_mode lab4_robot_interface/srv/SetRobotMode "mode: 2
target_pose:
  position:
    x: 0.0
    y: 0.0
    z: 0.0
  orientation:
    x: 0.0
    y: 0.0
    z: 0.0
    w: 1.0
teleop_frame: 0" 

```

#### Switch to Auto Mode (Mode 3)

The robot will automatically fetch targets from `/random_pose` via the `GetTarget` service and move using generated trajectories.

```bash
ros2 service call /set_mode lab4_robot_interface/srv/SetRobotMode "mode: 3
target_pose:
  position:
    x: 0.0
    y: 0.0
    z: 0.0
  orientation:
    x: 0.0
    y: 0.0
    z: 0.0
    w: 1.0
teleop_frame: 0" 
```

## Notes

- Always ensure the main system (Terminal 1) is running before switching modes
- When switching to Teleop Mode, make sure Terminal 2 has focus for keyboard control
- Use `Ctrl+C` to stop any running node safely
- The system includes singularity detection and will warn when the robot approaches singular configurations
- Ground collision checking is active - the robot will stop if end-effector $z < 0$

## Troubleshooting

- If RViz doesn't show the robot, check that `robot_state_publisher` is running
- If teleop doesn't respond, verify you're in Mode 2 and Terminal 2 has focus
- For build errors, ensure all dependencies are installed and workspace is sourced
